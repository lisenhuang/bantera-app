# Bantera 2.29.3 (407)

Prepared 20 October 2026. No commit, push or App Store submission.

## Changes

- The share-card badge now shows a localised local calendar date (yyyy.MM.dd in both Chinese variants), captured when the preview opens so the cached export and preview agree.

- Cue 1 audio controls sit beside the waveform below its text. Reply audio controls sit on the left; A/B labels are removed. Selected-answer feedback retains its border and status icon.

- Bottom navigation now contains Practice, Chats and Profile. Practice's 48-point ellipsis control opens a text-only “Longer dialogues” item, translated in all 17 app UI languages. The fixed 56-point toolbar retains a centred title, with level and daily goal on the right.
- Dialogues uses the existing page and library menu, pushed over Practice. Back retains the existing Practice state, answer, translation eligibility and completed recording. The menu is disabled while recording or processing, preventing navigation from discarding an active capture. Playback stops when leaving the page.
- Updated widget chat navigation, goal reminder destination and unread-chat icon for the three-tab layout. Existing deep-link URIs are unchanged; there was no Dialogues-specific external link to migrate.
- Online people discovery always excludes same-native-language strangers. Existing direct conversations remain visible; the optional menu setting is removed without deleting saved preferences.
- iOS deployment target is 15.0. Live Activity types/startup and widget APIs are availability guarded. The basic widget has an older-system background; normal CallKit remains available subject to the existing regional policy.
- Translation UI and execution are disabled on iOS 15–17, preserving stored translations and preferences. Translation actions cannot remove Practice level eligibility on those systems. Actual OS checks cannot be elevated by developer version mocks. iOS 18+ Apple translation and Android translation remain unchanged.
- Short speech recordings retain runtime-checked SFSpeechRecognizer support. Media SpeechTranscriber workflows still require iOS 26. Recognition service failures remain neutral retries.

## iOS 15 runtime blocker and release gate

This Mac runs macOS 27.0.1 and Xcode 27.1. Actual commands:

```
xcodebuild -downloadPlatform iOS -buildVersion 15.0
xcodebuild -downloadPlatform iOS -buildVersion 15.5
```

Both returned “not available for download.” Apple's compatibility table lists iOS 17+ simulator/device support for Xcode 27.1. Xcode 26.3 supports iOS 15 simulators but requires macOS 15.6–26.x, excluding this host. No existing Xcode or runtime was replaced.

Source: https://developer.apple.com/xcode/system-requirements

A compatible older Mac environment or a physical iOS 15 device is required before claiming full compatibility. Version mocks and an iOS 15 deployment target do not substitute for this test. Validate both fresh install and upgrade without data loss, auth providers, mic/speech permissions, supported/unsupported language recording, playback, Practice scoring/goals, saved material, notifications and interruptions. On a real phone also verify locked-screen incoming callback, two-way audio, speaker/receiver/Bluetooth routing and clean hangup. Installation permission alone is not authorization to place test calls.

App Store publication remains gated on that oldest-runtime/device acceptance. No new app API contract, database migration, environment variable or secret is required.
